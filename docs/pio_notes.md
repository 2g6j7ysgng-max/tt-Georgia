PIO notes (RP2040, гл. 3)

## 3.1 общее
- 2 PIO блока, в каждом 4 SM, работают параллельно
- память программ общая на блок: 32 инструкции по 16 бит, 4 порта чтения (по одному на SM), хост туда только пишет
- у каждой SM 2 FIFO: TX (хост -> SM) и RX (SM -> хост), каждая 4 слова по 32 бита
- можно склеить TX+RX в одну FIFO на 8 слов в одну сторону
- IO mapping: мукс между SM и пинами, на каждый пин out / oe / in
- в RP2040 доступ через AHB-Lite, у меня вместо этого будет SPI от хоста
- одна SM по площади примерно как обычный SPI/I2C контроллер

## 3.2.2 исполнение
- каждый такт: fetch + decode + execute одной инструкции
- 1 инструкция = 1 такт, если нет stall
- после инструкции задержка [N], до 31 такта
- поле [12:8] (5 бит) делится между delay и side-set
  макс delay = 2^(5 - sideset_bits) - 1
  в uart_tx sideset 2 бита -> delay до 7
- PC: +1, на wrap_top прыгает на wrap_bottom без jmp, jmp ставит PC явно
- делитель частоты 16.8 (16 бит целая часть, 8 дробная)
  пример: div 2.5, программа на 4 такта -> период 10 тактов sys_clk
- хост может стартовать/стопать SM, несколько сразу синхронно

squarewave:
  set pins, 1 [1]   2 такта
  set pins, 0       1
  jmp again         1
  итого период 4

## 3.2.3 регистры
OSR 32 бит  - на выдачу. pull кладёт слово из TX FIFO, out выдвигает 1..32 бита, освободившееся заполняется нулями
ISR 32 бит  - на приём. in вдвигает 1..32 бита, push отправляет в RX FIFO и обнуляет ISR
X, Y 32 бит - счётчики / временные, источник условий для jmp
PC 5 бит

скрытые:
- out shift counter: 0..32, при сбросе = 32 (OSR пустой)
  out +n, успешный pull -> 0, mov в OSR -> 0
- in shift counter: 0..32, при сбросе = 0
  in +n, успешный push -> 0, mov в ISR -> 0, out isr, n -> n
- 0..32 это 33 значения, значит счётчикам нужно 6 бит, не 5
- счётчик задержки (5 бит) в даташите отдельно не описан, но нужен

прочее:
- направление сдвига OSR/ISR задаётся конфигом
- in null вдвигает нули, нужно для выравнивания байта при LSB-first (uart)
- autopull/autopush: автоматически при достижении порога счётчика (3.5.4)

## откуда берутся инструкции
- память программ (обычный режим)
- SMx_INSTR: хост пишет инструкцию, она выполняется сразу (forced). удобно для настройки: set x 0, jmp на начало
- mov exec: инструкция из регистра
- out exec: инструкция из данных OSR, так в i2c вставляют stop/restart
- у mov exec / out exec сама команда 1 такт, вложенная выполняется на следующем

## группы пинов (5 шт)
out      - out pins / out pindirs, до 32
set      - set pins / set pindirs, до 5
side-set - поле sideset, до 5
in       - in pins, wait pin. задаётся только база
jmp pin  - для jmp pin, 1 пин
группы могут пересекаться (в uart_tx out и side-set на одном пине)

## 3.2.4 stall
PC не меняется, на след такте та же инструкция
задержка стартует только ПОСЛЕ окончания stall

когда stall:
1. wait, условие не выполнено
2. pull block при пустом TX FIFO / push block при полном RX FIFO
3. irq wait, ждёт пока флаг сбросят
4. out при autopull, OSR на пороге (подробно 3.5.4)
5. in при autopush, ISR на пороге и RX FIFO полный

side-set срабатывает сразу, даже во время stall (3.5.1)

## кодировка (3.4.1)
[15:13] опкод | [12:8] delay/side-set | [7:0] аргументы
000 jmp, 001 wait, 010 in, 011 out, 100 push/pull, 101 mov, 110 irq, 111 set

## JMP (3.4.2)
000 | cond [7:5] | addr [4:0]
- cond: 000 всегда, 001 !x (x==0), 010 x-- (x!=0), 011 !y, 100 y--, 101 x!=y, 110 pin, 111 !osre (OSR не пуст)
- delay выполняется всегда, взят прыжок или нет, и после обновления PC
- x-- / y--: декремент всегда, решение по значению ДО декремента
- адрес абсолютный -> при загрузке программы не с 0 прыжки надо сдвигать

## WAIT (3.4.3)
001 | pol [7] | source [6:5] | index [4:0]
- stall пока условие не выполнено, delay только после
- pol 1 = ждать 1, pol 0 = ждать 0
- source:
  00 gpio - абсолютный номер пина, маппинг in не применяется
  01 pin  - in_base + index (mod 32)
  10 irq  - флаг irq номер index
  11 reserved
- wait 1 irq: когда флаг поднялся, SM сама его сбрасывает
- index для irq как в инструкции IRQ: [2:0] номер флага, [4] rel (+ номер SM)

## IN (3.4.4)
010 | source [7:5] | bitcount [4:0]
- вдвинуть bitcount бит из source в ISR, счётчик ISR += bitcount (max 32)
- bitcount 32 = 00000
- source:
  000 pins (маппинг in), 001 x, 010 y, 011 null (нули)
  100 reserved, 101 reserved, 110 isr, 111 osr
- берутся младшие bitcount бит источника
- направление сдвига ISR задаётся конфигом
- stall: при autopush, если ISR на пороге и RX FIFO полная

## OUT (3.4.5)
011 | dest [7:5] | bitcount [4:0]
- выдвинуть bitcount бит из OSR в dest, счётчик OSR += bitcount (max 32)
- bitcount 32 = 00000
- dest: 000 pins, 001 x, 010 y, 011 null, 100 pindirs, 101 pc, 110 isr (+ счётчик ISR = bitcount), 111 exec
- сдвиг вправо -> младшие биты OSR, влево -> старшие, остальное нули
- pins / pindirs по маппингу out
- out pc = безусловный прыжок
- out exec: delay самого out игнорируется, у вложенной инструкции работает

## PUSH (3.4.6)
100 | 0 [7] | iffull [6] | block [5] | 00000
- ISR -> RX FIFO, ISR = 0
- iffull 1: ничего не делать, пока счётчик ISR не дошёл до порога
- block 1: stall если RX FIFO полная

## PULL (3.4.7)
100 | 1 [7] | ifempty [6] | block [5] | 00000
- TX FIFO -> OSR
- ifempty 1: ничего не делать, пока счётчик OSR не дошёл до порога
- block 1: stall если TX FIFO пустая (по умолчанию block)
- noblock при пустой TX FIFO: в OSR копируется X (не stall)
- при autopull pull ничего не делает, если OSR ещё не пуст

## MOV (3.4.8)
101 | dest [7:5] | op [4:3] | source [2:0]
- dest:
  000 pins (маппинг out), 001 x, 010 y, 011 reserved
  100 exec (выполнить значение как инструкцию)
  101 pc (= безусловный прыжок)
  110 isr (счётчик ISR -> 0), 111 osr (счётчик OSR -> 0)
- op: 00 ничего, 01 инверсия (~), 10 разворот бит, 11 reserved
- source:
  000 pins (маппинг in), 001 x, 010 y, 011 null
  100 reserved, 101 status, 110 isr, 111 osr
- status = все 1 или все 0 в зависимости от уровня FIFO (конфиг status_sel, status_n)
- mov exec: сам mov 1 такт, его delay игнорируется, вложенная инструкция на следующем такте со своим delay
- nop = mov y, y

## IRQ (3.4.9)
110 | 0 [7] | clr [6] | wait [5] | index [4:0]
- clr 1: сбросить флаг (wait тогда не влияет)
- clr 0: поднять флаг
- wait 1: после подъёма stall, пока флаг кто-то не сбросит
- index [2:0] = флаг 0..7, [4] rel: прибавить номер SM к двум младшим битам (mod 4)
- флаги 0..3 можно вывести наружу как прерывание, 4..7 только между SM
- у меня: флаги 0..3 -> пин IRQ на хост

## SET (3.4.10)
111 | dest [7:5] | data [4:0]
- dest: 000 pins, 001 x, 010 y, 100 pindirs, остальное reserved
- x / y: младшие 5 бит = data, остальные 0
- reserved коды (set 011/101/110/111, wait source 11) — место под свои расширения

## 3.5.1 side-set
- до 5 пинов, база и количество в конфиге
- opt: старший бит поля [12:8] = флаг "side-set есть" (тратит 1 бит)
- биты side-set отнимаются от delay
- side_pindir: side-set меняет направление пинов, а не значение
- срабатывает в первом такте инструкции, даже если она в stall
- если side-set и out/set пишут один пин в одном такте, побеждает side-set

## 3.5.2 wrap
- wrap_top, wrap_bottom в конфиге (по умолчанию 31 и 0)
- если PC == wrap_top и прыжок не взят -> PC = wrap_bottom
- взятый jmp важнее wrap
- бесплатно, без лишнего такта
- в pioasm: .wrap_target (bottom), .wrap (top)

## 3.5.3 FIFO join
- fjoin_tx: обе FIFO работают как одна TX на 8 слов, RX отключена
- fjoin_rx: наоборот
- в RTL: одна память на 8 слов, режим выбирает кто её использует

## 3.5.4 autopush / autopull
счётчики: 6 бит, насыщение на 32, сброс isr=0 osr=32
порог 1..32 (0 = 32)

autopush, такт IN (всё за 1 такт):
  isr = shift(isr, in); cnt = sat(cnt + n)
  if cnt >= thresh: rx full -> stall, иначе push, isr = 0, cnt = 0

autopull, такт НЕ out (фон):
  if mov osr или pull: cnt = 0
  if cnt >= thresh и tx не пустая: osr = pull, cnt = 0
  -> перезаливка может случиться в любой момент между двумя out

autopull, такт OUT:
  if cnt >= thresh:  (osr пуст)
    если tx не пустая -> osr = pull, cnt = 0
    stall В ЛЮБОМ СЛУЧАЕ (нельзя залить и выдать в одном такте)
  else:
    выдать биты, сдвиг, cnt += n
    if cnt >= thresh и tx не пустая -> osr = pull, cnt = 0 (параллельно, бесплатно)

подводные камни:
- mov из osr при autopull = неопределённо
- mov в osr не перезапишется autopull'ом (mov обнуляет счётчик)
- pull при autopull = fence: osr полон -> nop, пуст -> ждёт данные
- pull ifempty / push iffull используют те же пороги
- pull ifempty нужен, чтобы выбрать, на какой инструкции SM стоит без данных

решить в своём дизайне:
- застрявший in не должен сдвигать isr повторно -> проверять fifo до записи
- фоновая перезаливка: только при clk_en и включённой SM (моё решение)

пример auto_push_pull (порог 32, autopush + autopull):
  .wrap_target
  out x, 32
  in x, 32
  .wrap
- TX FIFO -> X -> RX FIFO, одно слово за 2 такта
- первый out после пустой FIFO теряет 1 такт на перезаливку
- хороший второй тест для RTL после uart_tx

## 3.5.5 делитель
- clkdiv int 16 бит + frac 8 бит, int = 0 значит 65536
- делитель выдаёт clock enable, а не новый клок -> SM делает шаг только когда en = 1
- div = 1.0 -> каждый такт
- при дробной части шаги неравномерные (то n, то n+1 тактов), в среднем точно
- в RTL: один клок, счётчик-аккумулятор, сигнал clk_en

## 3.5.6 GPIO
- out: base + count (0..32)
- set: base + count (0..5)
- side-set: base + count (0..5)
- in: только base, номер = base + i (mod 32)
- jmp pin: один пин
- значения пинов и направления — регистры, держатся пока не перезапишут
- если две SM пишут один пин в одном такте, побеждает SM с большим номером
- на входах GPIO 2-триггерный синхронизатор (+2 такта), можно отключить в конфиге
- у меня: синхронизатор на всех протокольных входах обязателен

## 3.5.7 forced / exec
- запись в SMx_INSTR: инструкция выполняется сразу, вместо выборки из памяти
- работает и когда SM остановлена -> так хост настраивает пины, X, Y, PC
- если forced инструкция ушла в stall, SM висит на ней, есть флаг exec_stalled
- out exec / mov exec: сама команда 1 такт, вложенная на следующем
- поведение delay у forced инструкции — проверить по 3.5.7

## разбор uart_tx (3.6.3)

.side_set 1 opt -> поле [12:8]: [12] флаг side-set есть, [11] значение, [10:8] delay (до 7)

| адрес | hex  | инструкция             | тактов |
|-------|------|------------------------|--------|
| 0     | 9FA0 | pull block side 1 [7]  | 1+7=8  |
| 1     | F727 | set x, 7 side 0 [7]    | 1+7=8  |
| 2     | 6001 | out pins, 1            | 1      |
| 3     | 0642 | jmp x--, 2 [6]         | 1+6=7  |

9FA0: 100|1|1|111|1 0 1 00000  -> pull, side 1, delay 7, block
F727: 111|1|0|111|001|00111    -> set, side 0, delay 7, dest X, data 7
6001: 011|0|0|000|000|00001    -> out, side-set нет, delay 0, dest PINS, 1 бит
0642: 000|0|0|110|010|00010    -> jmp, side-set нет, delay 6, cond X--, addr 2

как работает:
- pull ждёт байт, side 1 держит TX = 1 (idle), даже во время stall
- set x 7: X = 7 (счётчик 8 бит), side 0 -> TX = 0, это старт-бит
- out pins 1: выдать младший бит OSR на TX (сдвиг вправо = LSB first)
- jmp x--: если X != 0 -> X--, назад на out. X уменьшается всегда
- после jmp wrap возвращает на адрес 0 без лишнего такта

такты на бит:
- старт: set = 8
- данные: out + jmp = 1 + 7 = 8
- стоп: pull = 8 (если FIFO пустая, больше: stall, TX держится в 1)
- последний бит данных тоже 8: delay у jmp выполняется даже если прыжка нет
=> 1 бит = 8 тактов SM => clkdiv = clk_sys / (8 * baud)

что хост делает при настройке (из uart_tx_program_init):
- TX = 1 и направление выход: в SDK через forced set pins / set pindirs
  -> нужна команда "выполнить инструкцию"
- out shift вправо, без autopull -> конфиг направления сдвига и autopull
- out pins и sideset pins на один пин -> конфиг баз групп пинов
- fifo join TX -> одна FIFO на 8 слов
- clkdiv -> делитель 16.8
- sm_init, set_enabled -> сброс и старт SM
- putc = запись в TX FIFO
